## 港区で分かった型 — 他区でも同じはず

**「一覧が無い」ではなく「探し方が違う」ことがある。** 港区は統合一覧を持たない代わりに、
**種別ごとに 12 本の CSV** を緯度経度つきで公開していた。都のカタログ検索では
「区役所・総合支所」の 12 行しか見えず、一覧が無いと誤判断していた。
対応後、港区の到達不可率は **35.1% → 2.8%**（ホスト 11 → 55 件）。

踏んだ罠 3 つ。他区でも確認すること。

1. **第1分類を使わない。** 「図書館・文化・スポーツ施設」のような複数種別の見出しで、
   屋内プールまで図書館に一致する。港区は「第2分類」を使う
2. **名称から判定できない施設がある。** 「芝の家」「国際交流スペース」
   「◯◯区民協働スペース」。種別列がある出典では種別列を優先する
3. **区の独自ポータルは自動取得を弾く。** 港区は curl に HTML を返した。
   その場合はユーザーに手元でダウンロードしてもらう

## 江東区・大田区・中野区で足された型

5. **フォルダ名で区を決めない。** 「北区」として渡されたフォルダの中身が

   一致率では選べないが、**列全体の一意率**（1.00 対 0.06 / 0.04）と

7. **同じ「分室」でも中身が違う。** 中野区の「中央図書館◯◯小学校分室」3 件は
   閲覧席・自習室・ソファーがあり火木土日 10–19 時開館なので**残す**。
   江戸川区の「◯◯小学校図書館サテライト」は返却ポストだけなので**落とす**。
   名称の形が似ていても、開館時間と設備の列を見れば分かれる
8. **高齢者向け施設の呼び名は区ごとに変わる。** 中野区は高齢者会館を
   「健幸プラザ」へ改称しており（11 件）、`HOST_POLICY_EXCLUDE` の「高齢者」に
   一致しない。**種別パターンにも一致しないので今は落ちているが、

## 足立区・台東区・目黒区・北区で足された型

11. **KML・xlsx は CSV へ書き出してから通す**（`--normalize facilities` は CSV 専用）。
    足立区は KML 10 本、北区・大田区は xlsx。`.venv` に `openpyxl` を入れてある。
    KML は `geopandas.read_file` で読め、`geometry.x/.y` を経度・緯度にする
12. **KML の分類列は「第1分類」だった。** 足立区 `cimuunity-center.kml` の種別は
    「**住区センター・児童館・悠々館**」で、これを種別列として渡すと
    「児童館」に一致し、**住区センター 47 件が全部児童館として入る**。
    港区で踏んだ罠と同型。**この KML は種別列を落として名称だけで通した**
13. **「入れないほうが正しい」ファイルを見分ける。** 足立区の住区センター 47 件は
    **45 件が既存ホスト（P14 児童館・図書館）の 100m 以内**で同一建物だった。
    地域学習センターは 14 件中 13 件。名称が違うので重複除去も効かない。
    → **種別パターンを足さない**（ファイル自体は渡す。他のパターンに当たる行だけ入る）
    - 逆に葛飾区の地区センターは 22 件中 14 件、渋谷区の社会教育館は 5 件中 5 件が
      独立していた。**同じ「取りこぼし」に見えても実態は逆になる。
      パターンを足す前に既存ホストとの距離を測ること**
14. **座標が無い区は住所の町名で区を裏取りする。** 目黒区の施設白書は
    座標が無く、住所も「上目黒二丁目19番15号」で区名が無い。
    区名を前置しないと座標化できないが、**フォルダ名を信じてはいけない**
    （5. の轍）。位置参照情報で 23 区すべてと照合し、
    **319/324 行が目黒区で当たり、次点の港区は 13 行**だったことを確認してから
    「東京都目黒区」を前置した
15. **「X座標」「Y座標」はどちらが緯度か分からない。** 台東区は X が経度だが、
    平面直角座標系なら X は北（緯度相当）。`COLUMN_MAP` には推測で置き、
    `resolve_column` の値域検査に判定を委ねている（範囲外なら中身から探し直す）

## 手順

```bash
source .venv/bin/activate

# 1. 落としたファイルの列を見る
python -m etl.fetch --inspect <ファイル>

# 2. 投入（下の一覧をそのまま使い、新しいファイルを末尾に足す）
# 3. 再ビルド → 検証 → 公開
python -m etl.build --live --sensitivity
python -m etl.selftest && node tools/parity_check.mjs
cd web && npm run deploy
```

## 変えてはいけない方針

- **`schema.HOST_POLICY_EXCLUDE`** — 高齢者向け施設（地域交流館・シニア活動館・
  高齢者◯◯）は供給側に数えない。ユーザーの判断。基準は
  「感覚過敏で限界が来た人が実際に入れる場所か」
- **スポーツ施設は入れない**（騒がしい）。**名称の経路で破られていたので
  「体育館」「スポーツセンター」を除外に入れた** — 目黒区「目黒区民センター体育館」が
  「区民センター」に、葛飾区「奥戸総合スポーツセンター（温水プール館・エイトホール）」が
  「ホール」に一致していた
- **廃止・休館中の施設は入れない**（「旧」「休館」「閉館」）。
  廃止済み 8 件が現役ホストとして数えられていた
- **公園は入れない** — 屋外であり、かつ負荷側の減点レイヤー（green）で既に
  使っているため二重になる。※港区 162 件をどうするかはユーザー未決
- **名称・ファイル名・列名から意味を当てない。決め手が無ければ落とす**
  （`CLAUDE.md` の「壊れ方の型」）
- **「会館」を単独の種別パターンにしない** — 「北烏山東敬老会館」（世田谷区）を
  拾って `HOST_POLICY_EXCLUDE` を素通りする。文京区の町会会館も対象外。
  「区民会館」「地区会館」「コミュニティ会館」「区民館」のように限定する
- **学童クラブ・ぴよぴよ・きっずクラブは入れない** — 登録児童／乳幼児親子しか
  入れず、かつ同一座標に親施設の行が別にある二重計上（練馬・新宿 32 行中 31 行、
  江東区のきっずクラブは 10 行すべてで確認）
- **集会所は入れる**（2026-07-30、ユーザーの判断）— 区民館・コミュニティ会館を
  数えて集会所を落とすと、線引きが施設の性質ではなく区の呼び方で決まる。
  ただし**予約制の無人貸室を供給側に数えている**という過大計上が残る
  （`docs/issues.md` に独立した項目として立ててある）
