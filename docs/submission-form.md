### 1-9 運用体制のイメージ

```
OSS として公開する（ETL・スコアリング・地図 UI・検証ツール一式）。区や事業者が
自分の施設データで回せる形にしてあり、対象地域も重みも設定で差し替えられる。

そのうえで目指すのは、東京都が主体となって実際の設置を検討する段階まで届くこと。
この地図は 9,507 区画を「人が話し合う価値のある十数区画」まで絞る道具であって、
どこに置くかを決める道具ではない。決めるのは人で、その会議に出せる根拠を作る。

運営形態についても案がある（ただし後述のとおり、これはデータから導いたものではなく
提案である）。当日・短時間の利用は無料を既定とし、有料になるのは予約と延長、および
民間商業施設での提供に限る。支払いは東京都のアプリのポイントや既存のキャッシュレス
決済に載せ、ミライロID は連携する。

無料を既定にするのは、入口の摩擦がそのまま到達不可を作るからである。この空間が
要るのはパニック・感覚過負荷の最中で、そのときに最初にできなくなるのが「アプリを
開く・認証する・支払う」という操作である。地図が「700m 以内に施設が無い」を数えて
いるのと同じ意味で、受付・決済・ID 提示はそれぞれ到達不可を作る。

同じ理由で、ミライロID の役割は「割引対象であることの証明」ではなく「優先予約・
延長枠の付与」に置く。手帳で証明できるのはこの空間を必要とする層の一部にすぎず
（未診断の人・手帳を申請していない人・子ども・妊娠中・外国人旅行者）、
「証明できなければ通常料金」は支援の網から最も外れている層に課金する設計になる。
連携は捨てず、向きだけを変える。

認証ログは「障害の有無 × 場所 × 時刻」の記録になる。料金区分の判定だけを行い、
本人を特定できる情報は保持しない設計を前提とする。

財源は課金ではなく、合理的配慮の履行コスト（障害者差別解消法の改正により
2024年4月から民間事業者にも義務化）および公共施設の運営費として扱う。手本にするのは
コインロッカーではなく授乳室である——小さな専用個室で、無料が当然で、誰も従量課金を
主張しない。どちらを手本にするかで下流の設計がすべて決まる。

なお、この運営案はオープンデータから導いたものではなく作者の提案であり、地図の
算出根拠とは種類が違う。当事者による検証も経ていない。両者を分けて記述している
（docs/operation-idea.md）。
```

### 3-1 技術選定の理由（上限 310 字）

```
ETLはPython（geopandas・shapely・pyproj）、UIはTypeScript＋MapLibre GL＋Vite、
配信はCloudflare Workers。サーバを持たない静的配信にしたのは、生成物をリポジトリに
置けば誰でも同じ地図を再現できるからです。重みスライダーのため同じ数式をPythonと
TypeScriptに2つ持つので、全9,507区画でスコアの一致を検査するツールを別に書きました。
距離は緯度経度ではなく平面直角座標EPSG:6677で測り、表の件数・地図に光る点・一覧の
行数が構造的にずれないようにしています。
```

### 3-2 生成AI等の活用方法（上限 310 字）

```
Claude Code（Claude Opus）で設計・実装・文書まで通しました。工夫したのは「AIに
検算をさせない」ことです。仕様書からの推測で列名を決め打ちし、全件NaNのまま既定値が
全メッシュに乗り、ビルドもテストも成功と表示された事故を最初に踏みました。以後、
数値に影響する列は中身で判定し、特定できなければ実際の値を添えて例外で止めます。
出典リンクも「開けること」ではなく「読んだファイル名がその先にあること」を検査し、
文書の現況値が配信データと合っているかもCIで落とします。
```
