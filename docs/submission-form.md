> 「共通する区画は 0 件」が来ると、初見の人には「答えが出ない道具」に読める**
> ——順序が作れない字数なら、置かないほうが正確に伝わる。
> 代わりに「唯一の正解は出しません／重みは動かせます」は残してある。

## 3. 技術詳細

> **310 字は「方法論を語る」には短すぎる。** 3 欄とも、方法を 1 文で名乗って
> あとは具体（層・区画数・出力）で埋めてある。**方法論は読み手が結論する**もので、
> 「方法論を提案します」と書いて伝わるものではない（同じ理由で、2 分の動画でも
> その言葉は使わない——画面が根拠を辿れることを見せれば、視聴者が自分で結論する）。

### 3-1 技術選定の理由（上限 310 字）

```
ETLはPython（geopandas・shapely・pyproj）、UIはTypeScript＋MapLibre GL＋Vite、
配信はCloudflare Workers。サーバを持たない静的配信にしたのは、生成物をリポジトリに
置けば誰でも同じ地図を再現できるからです。重みスライダーのため同じ数式をPythonと
TypeScriptに2つ持つので、全9,507区画でスコアの一致を検査するツールを別に書きました。
距離は緯度経度ではなく平面直角座標EPSG:6677で測り、表の件数・地図に光る点・一覧の
行数が構造的にずれないようにしています。
```

### 3-2 生成AI等の活用方法（上限 310 字）

```
Claude Code（Claude Opus）で設計・実装・文書まで通しました。工夫したのは「AIに
検算をさせない」ことです。仕様書からの推測で列名を決め打ちし、全件NaNのまま既定値が
全メッシュに乗り、ビルドもテストも成功と表示された事故を最初に踏みました。以後、
数値に影響する列は中身で判定し、特定できなければ実際の値を添えて例外で止めます。
出典リンクも「開けること」ではなく「読んだファイル名がその先にあること」を検査し、
文書の現況値が配信データと合っているかもCIで落とします。
```
