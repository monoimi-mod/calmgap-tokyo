## A. 結論を歪めている疑いのある偏り

### A1. 騒音レイヤーが実質「世田谷区ダミー」として働いている 🔴最優先

負荷レイヤーのうち騒音だけが、他の全レイヤーと**逆向き**に動いている。

| | 世田谷区ダミーとの相関 |
|---|---|
| **自動車・鉄道騒音** | **+0.484** |
| 精神科・心療内科 | −0.632 |
| 駅乗降規模 | −0.623 |
| 混雑（従業者数） | −0.532 |
| 用途地域 | −0.471 |
| 障害福祉サービス事業所 | −0.159 |

原因は内挿ではなく **測定地点の選ばれ方**。内挿値と最寄り測定点までの距離の相関は
+0.030 しかなく、「測定点から遠いから低い」のではない。区内の測定点そのものが

| 区 | 点数 | 平均 | 最小〜最大 |
|---|---|---|---|
| 世田谷区 | 24 | 70.3 dB | 62〜76 |
| 渋谷区 | **5** | 67.6 dB | 66〜69 |

で、**区ごとに違う性格の道路が選ばれている**。要請限度測定は「苦情の出る道路」を
測る調査で、面的な騒音分布を代表しない。

影響は決定的で、**世田谷区が上位に入っている理由の大半がこの 29 点**である。

| 上位 50 メッシュの区内訳 | 渋谷区 | 世田谷区 |
|---|---|---|
| 現状 | 31 | 19 |
| **騒音レイヤーを外す** | **46** | **4** |

対応の候補（次回に判断する）。

1. 重みを下げる。ただし「不利なので下げた」ことにならない根拠が要る
2. 用途地域側へ寄せて騒音レイヤー自体を落とす（8.12 の主張は失う）
3. 鉄道騒音（`tokyo_rail_noise`）を足して測定点の性格を揃える
4. 「幹線道路からの距離」を N02/道路データから作り、測定値ではなく**構造**で面を作る

**いずれにせよ、現状のまま「世田谷にも上位がある」と言ってはいけない。**

```bash
# 再現
PYTHONPATH=. python - <<'PY'
import geopandas as gpd, numpy as np
from etl.config import CRS_PROJECTED
area=gpd.read_file('data/processed/area.geojson').to_crs(CRS_PROJECTED)[['ward','geometry']]
area.columns=['w','geometry']
m=gpd.read_file('web/public/data/mesh.geojson'); mp=m.to_crs(CRS_PROJECTED)
m['ward']=gpd.sjoin(gpd.GeoDataFrame(geometry=mp.geometry.centroid,crs=CRS_PROJECTED),
                    area,how='left',predicate='within')['w'].to_numpy()
print(np.corrcoef(m['n_noise'], (m['ward']=='世田谷区').astype(float))[0,1])
PY
```

### A2. 「ターミナル性」を何重に数えているか検証していない

渋谷区は面積の 20.9% だが上位 100 メッシュの **64%** を占める。
方向としては妥当だが、その根拠になっている層が互いに強く相関している。

- 駅乗降規模 × 精神科 = 0.795（相関行列の最大値。閾値 0.9 に近い）
- 駅 × 混雑 = 0.602 / 混雑 × 用途地域 = 0.610 / 駅 × 用途地域 = 0.470
- 主成分分析：第 1 主成分の寄与率 40.6%、駅 +0.471 / 精神科 +0.451 / 混雑 +0.418 /
  用途地域 +0.386 が同符号で乗る

3 層（駅・精神科・混雑）をまとめて外すと上位 50 の **40% が入れ替わる**。
現在の点検は **2 変数間の相関しか見ておらず**、しかも「0.9 未満なら二重計上なし」
という閾値に根拠がない。3 層以上の共線性を測る手段（VIF・主成分）を入れて、
「ターミナル性が需要側と負荷側に二重で乗っていないか」を明示的に答える必要がある。

### A5. 供給側の密度が区で 1.5 倍違う理由が未確認

| 区 | ホスト施設 | 密度 |
|---|---|---|
| 渋谷区 | 32 | 2.10 件/km² |
| 世田谷区 | 176 | 3.05 件/km² |

渋谷区の公共施設一覧は 527 件あるのに、ホスト種別（図書館・区民センター・出張所等）と

「渋谷区は転用できる施設が少ない」という提言をするなら根拠が要る。

## B. 説明できていない（不透明さ）

### B1. 入力データの 74% が対象 2 区の外にある

エッジ効果を避けるため区界の外側 2km まで拾う設計（既知）だが、量が大きい。

| レイヤー | 対象 2 区内 | バッファ内（区外） |
|---|---|---|
| 障害福祉事業所 | 963 | **2,741** |
| 精神科・心療内科 | 207 | 480 |
| 駅 | 56 | 145 |
| 公園 | 410 | 940 |
| 騒音測定点 | 29 | 120 |

設計としては正しい。**問題は、画面にも文書にもこの比率が出ていないこと**。
「渋谷区のメッシュの需要が新宿区の事業所で決まっている」ことがあり得るのに、
根拠カードは徒歩圏の件数しか出さない。上位 50 のうち 7 件は最寄り駅が区外。

### B2. スコアは対象 2 区内の相対順位なのに、カードは絶対値に見える

「需要 0.99 × 負荷 0.98」は 1,116 区画の中での順位でしかない。
23 区に広げれば全部変わる。文書には書いてあるが、
**根拠カードの文面そのものには「1,116 区画中」の但し書きが無い**。

### B3. `proposals.json` の `ward` が常に空

`etl/hosts.py` の `build_proposals` がメッシュ側の `ward`（存在しない列）を入れている。
UI は `host_ward` を見るので表示上の実害は無いが、**配信データに意味の無い列が残っている**。
外部の人がこの JSON を読んだら誤解する。

### B4. 生成物が環境依存で 4 桁目までしか一致しない（既知・未解決）

用途地域の面積加重平均が GEOS のバージョン差で変わる。
上位 50 件の顔ぶれは不変だと確認済みだが、**公表数値は 1 環境に揃える**運用でしのいでいる。

## C. 出典そのものの限界

### C1. 年次が 15 年ぶん開いている

事業所 2026 / 駅 2024 / 混雑 2021 / 用途地域 2019 / **騒音 2013 / 公園 2011**。
公園と騒音が特に古い。世田谷区の公園はこの 15 年で増えているはずで、
減点レイヤーが過小になっている可能性がある。

### C2. P13 は都市公園法上の都市公園しか含まない

渋谷区 47 件・世田谷区 371 件。児童遊園・公開空地・大学キャンパス・
社寺境内の緑を含まない。**この 8 倍の差が実態か収録範囲かを確認していない。**
「屋外に代替の退避先が存在しない」という提言文が、この収録範囲に依存している。

### C3. 緑被覆が 0 のメッシュが 55.7%

`zero_is_absence=True` なので減点も 0。
「公園が全く無い」と「小さい公園がある」の差が付かない。
円近似の重なりは 0.3% しかなく、そこは問題ない。

### C4. 混雑は経済センサス 2021（コロナ期）の従業者数

テレワークの影響が入っている可能性がある。
そもそも従業者数は昼間人口ではない（既知）。

## D. 検証の穴

### D1. 感度分析がレイヤー重みしか揺すっていない

固定値のまま結果を左右しているもの:

- 種別重み 30 種・仮定員 25 種（A3）
- 帯域 `BANDWIDTH_M`（事業所 800m / 学校 1200m / 駅 600m / 精神科 800m）
- 用途地域 → 負荷スコアの写像（商業 1.00 / 第一種低層 0.05 など 13 値）
- ホスト優先度 `HOST_PREFERENCE` と割当上限 `HOST_MAX_DISTANCE_M = 700m`
- IDW の平滑化項 50m と打ち切り 1500m
- 合成指数 α = β = 1.0

「重みを変えても結論は変わらない」と言えるのは 8 レイヤーの重みについてだけ。

### D2. 相関の点検が 2 変数間だけ・閾値 0.9 に根拠がない（A2 と同じ）

### D3. 上位が変わったのに、その妥当性を外部と突き合わせていない

模擬データの頃は「上位 10 件がすべて渋谷駅 583m 以内」で直感に合った。
実データでは代々木・千駄ヶ谷・南新宿になったが、**これが妥当かを裏付ける
外部の材料が無い**。当事者検証が無い（既知）ことと合わせ、
サニティチェックが実質的に機能していない状態になっている。

### D4. 到達不可 29 件（2.6%）を目視で確かめていない

「700m 以内にホスト施設が無い」という提言の中身を、
実際に地図で見て「本当に何も無いのか」を確認していない。
A5（判定漏れの疑い）と直結する。

   鉄道騒音の測定点を落として測定点の性格をそろえられるか確かめる
2. **A3・D1 感度分析の対象を広げる** — 種別重み・仮定員・帯域まで揺さぶる。
   A2 の共線性指標（VIF か主成分）も同じ仕組みに乗せる
3. **A4・B3 表示の正直さ** — ラベルと配信 JSON を実態に合わせる（小さい）
4. **A5・D4 供給側の点検** — 渋谷区 32 件が判定漏れでないかを目視で確認
5. **B1・B2 根拠カードに但し書きを足す** — 「1,116 区画中」「徒歩圏には区外◯件を含む」
