### A10. 提言が、モデルの計算していない結論を述べていた ✅解消（2026-07-31）

**提言リストの見出しが施設名だった**（「上池袋図書館」「巣鴨図書館」…）。
本文にも「設置候補: 上池袋図書館（メッシュ重心から約527m）」と出ていた。
これは 3 つの意味で、出力できる根拠の無い主張だった。

1. **モデルに施設の適性を測る構成要素が一つも無い。** 需要も負荷もメッシュの
   属性から作っている。上位 10 件の見出しが図書館 7・区民センター 3 だったのは、
   区の公共施設一覧に何が載っていたか、それがたまたまどこに在ったか、そして
   例示の優先順位（`HOST_PREFERENCE` が図書館を 1 位にしている）の積であって、
   施設を評価した結果ではない。**にもかかわらず出力は「静かな施設を選んでいる」
   ように読める。** A1 や A29 の誤りと同じで、**もっともらしく見えることが
   そのまま発見を妨げる**型の壊れ方だった。
2. **名指しした建物が、分析した区画の中に無い。** 割当は半径 700m まで許して
   いるので、250m 区画の重心から 494〜677m 離れた施設が見出しに載っていた。
   分析の単位（250m）と主張の単位（特定の建物）が一致していない。
3. **名指しされる側は同意していない。** 公開 URL の見出しに実在の施設名を置けば、
   その建物への設置要求として読まれる。余剰空間も運営体制も測っていない。

**是正**: 提言の単位を「隣接する区画のまとまり（地区）」に変え、見出しを
**区名＋最寄り駅名**にした（「豊島区 池袋・北池袋周辺」）。束ねる根拠も
「同じ施設が最寄り」から「メッシュが格子の上で接している」へ移した
（`etl/mesh.py` の `grid_index`。整数座標だけで決まるので施設の配置に依存せず、
Python と TypeScript でズレる余地も無い）。供給側から言うのは
`f_host_n`（徒歩圏 700m の公共施設の件数）と到達可否だけになった。

**供給側のレイヤーは捨てていない。** 捨てると到達不可 1,058 区画（11.1%）が
出せなくなる。役割を「設置候補地」から**「徒歩圏に屋内の公共空間がそもそも在るか」の
代理指標**に言い換えただけで、後者は区画についての言明でありデータが支えている。

**残る限界**: `f_host_n` が数えているのは施設一覧の**行数**であって建物の数ではない
（下の「同じ建物が複数のホストとして数えられている」）。また対象は区立施設のみで、
都・国・民間の施設は入っていない。

### A2. 「ターミナル性」を何重に数えているか検証していない

- 駅乗降規模 × 精神科 = 0.795（相関行列の最大値。閾値 0.9 に近い）

- 主成分分析：第 1 主成分の寄与率 40.6%、駅 +0.471 / 精神科 +0.451 / 混雑 +0.418 /
  用途地域 +0.386 が同符号で乗る

3 層（駅・精神科・混雑）をまとめて外すと上位 50 の **40% が入れ替わる**。
現在の点検は **2 変数間の相関しか見ておらず**、しかも「0.9 未満なら二重計上なし」
という閾値に根拠がない。3 層以上の共線性を測る手段（VIF・主成分）を入れて、
「ターミナル性が需要側と負荷側に二重で乗っていないか」を明示的に答える必要がある。

### B3. `proposals.json` の `ward` が常に空 ✅是正済み（2026-07-30）

`etl/hosts.py` の `build_proposals` がメッシュ側の `ward`（存在しない列）を入れており、
全件が空文字だった。当時は提言が施設についてのものだったので `host_ward` を出して直した。

**A10 でこの判断は入れ替わった。** 提言の単位が地区になったので、意味があるのは
**メッシュ側の区名**のほうになり、`build_mesh_table` が行政区域との面積比から
`ward` 列を作るようにした（存在しない列を読んでいた元の誤りが、
「メッシュに区名が要る」という形で正しくなった）。

**同じ経路でもう 1 つ壊れていた。** `normalize_ward` が `str(value or "")` と
書かれていたため、区名の列が欠測（`float('nan')`）の行で **`"nan"` が区名として
持ち回られていた**。`nan` は真なので `or ""` を素通りする。結果、
**公開中の提言 10 件のうち 3 件に「ただしnanの施設であり、対象区の所管外。
区境をまたぐ連携が前提になる」と出ていた**——千代田図書館・富士見出張所・
神保町出張所はいずれも千代田区（対象区）の施設なので、注記の意味が逆である。

`normalize_ward` の docstring は「区名を揃えないと逆の注記が付く」と
警告していたが、**欠測の側から同じ穴に落ちていた**。
`selftest` に `normalize_ward(float("nan")) == ""` を入れてある。

なお 1,541 件のうち 273 件は区名の列そのものが無い出典から来ており、
`host_ward` は空になる。空なら注記は出ない（安全側）。
