# プレゼン（2 分）の構成と、提出用キャプチャ

提出フォームの **5-1 スライド（2 分・16:9）** と **5-2 画面キャプチャ（最大 3 枚・
1600×900）**、および **3-8 デモの操作動画（任意・60 秒・無音）** のための台本。

> **数値はビルドごとに動く。** 資料に載せる数字は、**凍らせたビルド 1 つ**から
> 取ること（`docs/status.md` と `python tools/doc_numbers.py`）。
> 本ファイルの数値は 2026-08-06 のビルド。

---

## 0. 方針 — 「方法論」という言葉を一度も使わない

主役は方法である。**だが 2 分でそれを言葉にすると死ぬ。**

審査員が「これは再現できる仕組みだ」と結論する経路は 1 つしかない——
**具体的な結論を見せられて、疑って、根拠を辿ろうとして、全部辿れてしまったとき。**
だから順番はこうする:

```
結論を出す → 根拠が全部辿れることを見せる → 立場を変えると変わることを見せる
→ それでも動かない部分を見せる → 外から確かめた結果を出す
```

**方法論は、最後に視聴者の頭の中に立ち上がる。**

## 1. 2 分の構成

| 秒 | 何を言う | 画面 |
|---|---|---|
| **0–15** | 感覚過敏のある人が街で過負荷になったときに退避できる場所が要る。設置は進み始めたが、**どこに置くかの基準は組織ごとにバラバラ**で、都全体の需給を俯瞰した公開資料が無い | タイトル |
| **15–35** | 公開データ 10 層だけで、需要 × 負荷から設置優先度を算出した。**東京 23 区・250m メッシュ 9,507 区画に実際に当てはめた** | キャプチャ①（全体） |
| **35–65** | **1 区画を開く。**「事業所 44 件・定員 394 人」「駅 1 駅・乗降計 135,911 人/日」「用途地域は商業地域」「推定騒音 67.6dB」——**実数・正規化値・地域内順位・出典・寄与が全部出て、数えた施設が地図で光る** | キャプチャ②（根拠） |
| **65–85** | **重みを動かす。** 立場が変われば順位も変わる。**4 つのプリセット全てで上位 20 件に入る区画は 0 件**——どこを優先すべきかは、何を重視するかに依存する | スライダー操作 |
| **85–105** | **だが、既存施設で届いていない場所は別に決まる。** 需要が高いのに徒歩 700m に区の公共施設が 1 件も無い **148 区画**。上位 50 とは 1 件も重ならない | キャプチャ③（148） |
| **105–120** | **外から確かめた。** 23 区で既に置かれているのは **11 か所・16 室**。優先度順位の中央値は **4,765 位**、上位 50 には **0 件**。そして**街を歩いている人がその場で使えるのは 1 室**——残りは大学の関係者のみ、保安検査後、入館料が要るもの | 外部照合の枠 |

**35–85 秒の 50 秒間、「方法論」とは一度も言わない。** 画面が実演する。

### 最後の 1 文（言い切る）

> 既存のカームダウンスペースは「その施設の利用者向けの設備」であって、
> **街にいる人の退避先ではありません。** この地図は、その差を 148 区画として示します。

## 2. 入れないもの

**2 分に入れると全部が薄くなる。** GitHub にある、と 1 行言うだけにする。

- 列名を中身で同定する仕組み（`require_column`）
- Python / TypeScript の全区画スコア一致検査（`parity_check`）
- selftest 71 件
- 順位化の副作用と絶対尺度への移行
- 固定値 76 個の感度分析

**技術的に最も誇るべき部分だが、2 分では絶対に伝わらない。**

### 限界は「言わない」のではなく「1 枚に畳む」

15 秒しか無いので、**いちばん重い 1 つだけ**を口に出す:

> 上位の顔ぶれは**特別支援学校というレイヤー 1 枚**でほぼ決まります（外すと上位 10 件が全部入れ替わる）。
> 順位を固定の答えとして読まないでください。

残り（当事者検証が 3 名のみ／多摩未対応／公園データが 2011 年／混雑が従業者数）は
スライドの隅に小さく並べる。**画面には全部書いてある**ので、
「詳しくは画面の『この分析で分からないこと』に」で足りる。

## 3. キャプチャ 3 枚（URL で再現できる）

**ディープリンクを入れたので、URL を開くだけで同じ状態になる。**
1600×900 で撮ること（ブラウザの開発者ツール →「スクリーンショットをキャプチャ」が確実）。

| # | 何を見せる | URL |
|---|---|---|
| ① | **結論**（2 枚のカード＋外部照合＋全体地図） | `https://calmgap-tokyo.hiroaki-kuwabara.workers.dev` |
| ② | **根拠が辿れること**（1 区画の内訳・出典・順位） | `…/#c=5339463631` |
| ③ | **148 区画**（一覧が全部「0 件」） | `…/#f=unreachable` |

②の区画は 1 位（江東区 亀戸）。③で先頭に出るのは 新宿区 新宿・西新宿・都庁前。

**3 枚とも `docs/captures/` にある。** 撮り直しは 1 コマンド:

```bash
node tools/shoot_captures.mjs
```

### `--virtual-time-budget` で撮ってはいけない（2026-08-07）

**仮想時間で早送りすると、9,507 区画が 1 つも描かれていない画像が出る。**
`#f=unreachable` で踏んだ——ベースマップと右のパネルは正しく写るので、
**縮小して見ると「そういう画面」に見える。** しかも**撮り直すたびに
バイト単位で同じものが出てくる**ので、再実行では気付けない。

原因はアプリ側ではない。同じ URL を普通のブラウザで開けば描かれる。
`requestAnimationFrame` の発火とメッシュのアップロードが仮想時間の
早送りと噛み合わないだけである。**実時間で待つ**ようにした（CDP 経由。
`tools/shoot_captures.mjs`）。

**自動で確かめられるのは「読み込み中でない・順位表が空でない」まで。**
地図ハンドルを外へ出しておらず、canvas も `preserveDrawingBuffer: false`
なので、**メッシュが描かれているかは検査できていない**——
だから撮ったら必ず画像を見る。

## 4. 60 秒の操作動画（任意・無音）

**この作品の見どころは「表の数字と地図の点が一致すること」なので、動画が最も雄弁。**

```
0–10s   全体地図。結論カード 2 枚が見えている
10–25s  順位表の 1 行を押す → 地図が寄る → 根拠と内訳が出る
25–40s  内訳の「障害福祉サービス事業所」を押す
        → 徒歩圏 800m の円が描かれ、44 件が光り、下に 44 行の一覧が開く
        →「表の 44 件・地図の 44 点・一覧の 44 行」が同じであることを見せる
40–50s  スライダーを動かす → 順位表が入れ替わる → 148 の数字も動く
50–60s  「絞り込んで地図に出す」→ 上位が消えて 148 区画が現れる
```

**40–50 秒を入れる理由。** 「重みで動く」ことを画面で見せないと、
**148 が動かない数だと誤解される**（かつて画面がそう書いていた）。

## 5. 使ってはいけない言い回し

過去に撤回した表現。**資料に混ぜないこと。**

| 使わない | 正しくは |
|---|---|
| 「徒歩圏に**退避先**が無い 148 区画」 | 「徒歩圏に**区の公共施設**が無い」——施設があっても設置されているとは限らない |
| 「148 は**重みに依存しない**」 | 重みで動く（プリセットで 133〜171 件） |
| 「屋外に代替の退避先が存在しない」 | 「この区画に緑・公園の被覆がほぼ無い」 |
| 「上位 10 件は◯◯区が…」（過去のビルドの数字） | **必ず凍らせたビルドから取り直す** |
| 「◯◯周辺」という地区名 | 区画単位。区名＋最寄り駅名は**呼び名**であって広がりの主張ではない |

## 6. スライドは HTML が原稿で、PDF が提出物（2026-08-07）

```bash
node tools/slides_pdf.mjs      # docs/slides.html → docs/slides.pdf
```

7 枚・16:9（960×540pt）・6.1MB。上の構成表の 6 区間に、限界の 1 枚を足した形。

**PPTX にしていない。理由は 2 つある。**

1. **フォントが置き換わらない。** 日本語のスライドは、相手の環境に
   そのフォントが無いと行が折り返して**レイアウトごと崩れる**。しかも
   **作った側の画面では正しく見える**ので、崩れたことに気付けない。
   PDF は字形を埋め込むので、審査員が開いた画面と手元の画面が同じになる
2. **数値が diff に出る。** この作品は「過去の数字を引用しない」を
   機械で守る仕組みを持っている。原稿がテキストなら、そこに載せられる

**まだ載せていない**——`tools/doc_numbers.py` は `docs/status.md` だけを
見ており、**この台本と `slides.html` と `submission-form.md` の数値は
検査対象の外にある**。3 つとも資料へ直接転記する数値を持っているので、
ここは塞ぐべき穴として残っている。

編集は `docs/slides.html` を直して書き出す。**PDF を直接直さないこと**
（次に書き出した瞬間に消える）。
